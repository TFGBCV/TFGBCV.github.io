Pipeline

Six moves, one auditable workflow

Use it as a desktop interface, or as a scheduler on a field laptop that nobody remembers is watching.

01CollectPlaywright + your session cookies read public content. Read-only, pseudonymised by default.
02ClassifyQwen2.5-VL 7B (bundled) flags GBV/hate in text and images — screenshots, ID cards, chat evidence.
03VerifyA devil's-advocate pass plus a lexicon safety net challenge every flag; disagreements go to review.
04EnrichEmbeddings find near-duplicates, template campaigns and burst waves; graph the amplifiers.
05ReviewConfirm / reject with one click. Confirmed decisions become memory with provenance stamps.
06DocumentPDF/Markdown reports with evidence chains, coordination graphs, κ stats and an audit log.
Capabilities

Built for defensible documentation

Three layers: what the AI reads, what it detects across pages, and what makes the output trustworthy.

🧠IntelligenceHow the local model reads your corpus

One local model handles text and images, and a rule-based net backs it up.

🖼️

Text + image screening

The shipped model reads both: captions and hate speech in text; NCII & sextortion-screenshot indicators in images. Conservative triage leads only.

👁️

Self-consistency voting

Multiple labelled passes vote on ambiguous items; the vote spread feeds the confidence score and the review-inbox ordering.

📚

Lexicon safety net

A keyword/regex net catches slurs and HR-violating phrases the model might miss — and baits the verifier pass with lexicon_attention.

🌐

Arabic-first prompts

MSA + Darija + French + English prompt pack; JSON-shaped verdicts with severity, categories and anchored quotes.

🕸️Coordination insightWhat emerges across pages and runs

Patterns that a single post never shows: repeated text, sudden waves, and who amplifies whom.

🧠

Verdict memory

Items you've confirmed or rejected are matched (≥0.97 similarity) across pages and runs — recurring content inherits your decision, stamped.

🧩

Duplicate & template detection

Near-duplicates, shingle fingerprints and distinct-author counts expose "same text, N accounts" patterns.

📈

Burst detection

σ-based wave detection versus each page's history — coordinated activity after a CEDAW debate, visible at a glance.

🕸️

Amplification graphs

PageRank/betweenness leaders over author ↔ page ↔ mention networks, exported as GraphML for external analysis.

🛡️Trust & operationsWhat makes the output usable by teams

Measured quality, scheduled runs, and exports that stand up to scrutiny.

⚖️

Quality dashboard

Cohen's κ between your reviews and the AI, per-category calibration, FN/FP stats — plus an eval harness so changes are measured, not vibes.

⏱️

Watchlists & background jobs

Register pages with cadences and budgets; the job engine runs due watchlists in the background — or wire the CLI into Task Scheduler.

🔐

Privacy by construction

Cookies held in RAM only, pseudonymised comments, optional SQLCipher encryption at rest, full local audit trail.

📄

Scrutiny-ready exports

PDF/MD/CSV/JSON with per-item evidence chains and fingerprints; longitudinal deltas; handover packs for partner orgs.

Install

Four ways in, one exe experience

All paths end the same way: a folder with GBVMonitor.exe that needs nothing else installed. Not sure which to pick? Start with Way 1.

🟢 Way 1 — download the release bundle Recommended · most teams

Download all attached files of the latest release into ONE folder (the bundle is split into 1.5 GB parts because of GitHub's asset limit), then reassemble and extract:

copy /b GBVMonitor-full.zip.001+GBVMonitor-full.zip.002+GBVMonitor-full.zip.003 GBVMonitor-full.zip

Right-click the zip → Extract All → open the folder → double-click GBVMonitor.exe. The console shows the local model loading (15–90 s), then your browser opens the interface.

⬇ Go to Releases

🟡 Way 2 — build it yourself Auditors · trust nothing

Clone the repo on Windows and run the one-shot build (installs a build venv, downloads the llama.cpp engine + models, packs everything):

powershell -ExecutionPolicy Bypass -File packaging\build_windows.ps1 -SkipZip

Flags: -SkipVulkan (CPU-only engine), -NoVision (skip the 1.35 GB vision tower), -ChatPrefix … (bundle a different model). A single setup.exe is optional via C:\Program Files\Inno Setup 7\ISCC.exe packaging\installer.iss.

🔵 Way 3 — bring your own models (LM Studio mode) Tech teams

Run the suite directly with Python 3.10–3.13 and point it at LM Studio, so you choose any local chat / embedding / vision model from the LM Studio catalogue:

pip install -r requirements.txt
python app.py            # web interface
python monitor.py run-due --enrich --verify   # scheduled CLI pass

Set GBV_VISION_MODEL to the ID of a downloaded vision model to enable image screening. Same privacy rules — nothing leaves 127.0.0.1 except Facebook reads.

🟣 Scheduler mode — weekly monitoring without a window Field laptops

The same exe runs headless commands for watchlists you've configured in the UI:

GBVMonitor.exe monitor run-due --enrich --verify
GBVMonitor.exe monitor watch --interval 900
GBVMonitor.exe monitor add-watch https://www.facebook.com/<page> --label "Darija monitoring" --cadence-hours 24

Wire it into Windows Task Scheduler (daily/weekly). Runs wake, process due watchlists with hard budgets, and stop — nothing idles in the background.

Facebook reality-check: automated collection violates Facebook's terms — use a dedicated (non-personal) account, keep cadences low, and expect account restrictions. The tool is designed for low-volume, schedule-driven, read-only monitoring; it is not a bulk-harvest scraper.
Privacy & ethics

Five hard rules, one posture

Not policies — constraints baked into the architecture. The AI proposes; a human always disposes.

1Read-only collectionNever likes, comments, follows or messages. Collection only, with hard budgets the agent cannot raise.
2Nothing leaves the machineAll models — chat, vision tower, embeddings — run locally. No cloud, no model API, no telemetry.
3Human in the loopThe agent proposes; a human approves every impact step — new targets, case writes, publication.
4Hard budgetsEvery run carries max_items / max_time / max_requests ceilings that cannot be exceeded unilaterally.
5Provenance firstEvery exported claim traces back to a SHA-256-anchored item — and your review log makes it defensible.
🍪 Cookies in RAM only — never written to disk 🎭 Pseudonymised by default 🔐 Optional encryption at rest (SQLCipher) 📜 Audit log of every run & export 🧎 Reviewer record signed on exports

FAQ

Questions, answered

Where does my data actually go?
Nowhere by default. Models run via llama.cpp on 127.0.0.1, the case database is local SQLite (optionally encrypted at rest), and exports happen only when you generate them. The only outbound traffic is reading the Facebook pages you chose.
Does it work offline?
After the first run the AI engine runs without internet. Facebook collection obviously needs a connection — that's the only outbound use.
Which languages are supported?
The prompt pack targets Arabic (MSA + Darija), English and French; the lexicon safety net carries LWY-adjacent Arabic slurs. You can extend lexicon.py without touching the model.
Can the AI decide what counts as evidence?
No — by design. Hard rules: read-only collection, human approval on every flag, hard budgets per run, SHA-256 provenance. The AI proposes, you dispose.
What hardware do I need?
Windows 10/11 x64, ~8 GB free RAM for the bundled 7B model (a 14B-class model wants ~14 GB), ~10 GB disk. CPU-only works; Vulkan GPUs make each run noticeably faster.
Can I share a case with a partner org?
Yes — export the report pack (PDF + CSV + JSON with provenance) or the case dataset itself. Nothing is uploaded by the tool: you hand over the files, and the receiving org sees exactly what your team confirmed or rejected.
